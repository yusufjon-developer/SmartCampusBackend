# 🛡 SmartCampusAuth — База данных для управления доступами пользователей

**SmartCampusAuth** — это отдельная база данных для централизованного управления доступами
пользователей к данным и функциям системы SmartCampus. Она предназначена для открытого проекта и
поддерживает гибкое назначение прав, управление отделами и суперпользователями (например, отделом
ИБ).

---

## 📁 Структура таблиц

### 🏢 Departments — Отделы

| Поле | Тип           | Описание                     |
|------|---------------|------------------------------|
| id   | int PK        | Уникальный ID отдела         |
| name | nvarchar(100) | Название отдела (уникальное) |

---

### 👤 Users — Пользователи

| Поле          | Тип           | Описание                        |
|---------------|---------------|---------------------------------|
| id            | int PK        | Уникальный ID пользователя      |
| username      | nvarchar(100) | Логин пользователя (уникальный) |
| password_hash | nvarchar(255) | Хэш пароля                      |
| email         | nvarchar(255) | Электронная почта               |
| full_name     | nvarchar(255) | Полное имя                      |
| role          | nvarchar(50)  | Роль (по умолчанию `'Student'`) |
| is_active     | bit           | Активен ли пользователь         |
| created_at    | datetime      | Дата создания записи            |

---

### 🧾 User_Departments — Связь пользователей с отделами

| Поле          | Тип        | Описание                             |
|---------------|------------|--------------------------------------|
| user_id       | int FK, PK | Ссылка на `Users`, пользователь      |
| department_id | int FK, PK | Ссылка на `Departments`, отдел       |
| is_manager    | bit        | Является ли менеджером в этом отделе |

> ✅ Один пользователь может принадлежать к нескольким отделам.

---

### 🛡 Superusers — Суперпользователи

| Поле    | Тип        | Описание                                   |
|---------|------------|--------------------------------------------|
| user_id | int PK, FK | Ссылка на `Users` — суперпользователь (ИБ) |

> 🧩 Суперпользователи имеют право выдавать любые разрешения и управлять доступами.

---

### 🔐 Permissions — Права доступа

| Поле        | Тип           | Описание                                        |
|-------------|---------------|-------------------------------------------------|
| id          | int PK        | Уникальный ID                                   |
| name        | nvarchar(100) | Название права (уникальное), напр. `ViewGrades` |
| description | nvarchar(255) | Описание действия, на которое даётся доступ     |

---

### 🗝 Access_Grants — Выданные права

| Поле          | Тип           | Описание                                     |
|---------------|---------------|----------------------------------------------|
| id            | int PK        | Уникальный ID записи                         |
| granted_by    | int FK        | Кто выдал (ссылка на `Users`)                |
| granted_to    | int FK        | Кому выдано (ссылка на `Users`)              |
| permission_id | int FK        | Какое право выдано (ссылка на `Permissions`) |
| grant_date    | datetime      | Когда выдано                                 |
| expires_at    | datetime NULL | Срок действия (может быть бессрочным)        |
| comment       | nvarchar(255) | Комментарий или причина выдачи               |

> 🔒 *Ограничение:* Один пользователь не может получить одно и то же право дважды.

---

### 📱 UserDevices — Устройства пользователей
| Поле          | Тип           | Описание                                                                  |
|---------------|---------------|---------------------------------------------------------------------------|
| id            | int PK        | Уникальный ID записи об устройстве                                        |
| user_id       | int FK        | Ссылка на Users — владелец устройства                                     |
| device_uuid   | nvarchar(255) | Уникальный идентификатор устройства (генерируется клиентом)               |
| device_type   | nvarchar(50)  | Тип устройства (например, `PC`, `ANDROID`)                                |
| is_approved   | bit           | Одобрено ли устройство администратором для использования (по умолчанию 0) |
| description   | nvarchar(255) | Описание устройства (например, "Рабочий ноутбук HP", "Мой Samsung A52")   |
| last_login_at | datetime NULL | Время последнего успешного входа с этого устройства                       |
| registered_at | datetime      | Время регистрации устройства в системе (по умолчанию GETDATE())           |
| approved_at   | datetime NULL | Время одобрения устройства администратором                                |
| approved_by   | int FK NULL   | Ссылка на Users — администратор, одобривший устройство                    |

> 📝 Примечание:•Для пользователей с ролью, отличной от 'Student', доступ к системе возможен только с is_approved = 1 устройства.•Один пользователь может
иметь не более одного одобренного устройства каждого device_type. При одобрении нового устройства
того же типа, предыдущее аналогичное устройство автоматически теряет статус одобрения.•Связь
approved_by указывает на пользователя из таблицы Users, который имеет права администратора (
например, является Superuser или имеет специальную роль/право). 

## 🔄 Связи между таблицами

```plaintext
Users ──────┐
            │
            ├─── User_Departments (многие-ко-многим → Departments)
            ├─── Superusers (1:1)
            ├─── Access_Grants (1:многие → Permissions)
            ├─── UserDevices (1:многие)  // Новая связь
Departments ┘
```

## ⚙️ Особенности и примечания

- Управление доступами централизовано: только сотрудники отдела ИБ (Superusers) могут назначать
  права.
- Все данные хранятся в `NVARCHAR` — поддержка Unicode.
- Структура БД допускает масштабируемость и расширение.
- Логгирование входов и сессий **отключено по умолчанию**.
- Нет отдельной сущности ролей: `role` — просто строковое поле.
- Простой контроль активных пользователей через `is_active`.
- Управление устройствами: Для пользователей с ролью, отличной от `Student`, введена система одобрения устройств. Каждый такой пользователь может иметь одно одобренное ПК-устройство и одно одобренное Android-устройство. Администраторы (например, из отдела ИБ) управляют одобрением через специальный интерфейс.

## 🌐 Использование с Ktor API

Проект предусматривает реализацию REST API с использованием Kotlin + Ktor. Доступы к другим базам (
например, SmartCampus) будут контролироваться через `Access_Grants`.
